\section{Executive Summary \& Audit Findings on stow.mystorage.vn}

By testing \href{https://stow.mystorage.vn}{\texttt{stow.mystorage.vn}} from the perspective of an actual prospective customer and cross-referencing its responses against the official website and the canonical \href{https://mystorage.vn/llms.txt}{\texttt{/llms.txt}} knowledge base, I identified three high-impact issues directly affecting \textbf{Revenue} and \textbf{Customer Trust}.

\subsection*{Finding 1: Scoping Error \& Policy Hallucination in Insurance Compensation}

\begin{criticalbox}
\textbf{What Happened}
\begin{enumerate}[leftmargin=1.5em]
  \item When asked about compensation for a 3 m\textsuperscript{3} unit under the Basic tier, STOW asserted: \textit{``Dạ với gói bảo hiểm cơ bản (Basic)... mức bồi thường tối đa là 10.000.000 VNĐ ạ''} (Under Basic protection, maximum payout is 10,000,000 VND). STOW conflated the \textbf{theoretical global plan cap} with the \textbf{actual per-unit compensation limit} derived from its volume (3 m\textsuperscript{3} $\times$ 500,000 VND = \textbf{1,500,000 VND}).
  \item When asked about paid protection tiers (tested in both Vietnamese \textit{``Bạc, Vàng, Bạch kim''} and English \textit{``Silver, Gold, Platinum''}), STOW flatly denied their existence: \textit{``Dạ hiện tại MyStorage \textbf{không} có các gói tên Bạc, Vàng hay Bạch kim ạ''} (MyStorage currently does not have tiers named Silver, Gold, or Platinum), despite these tiers being documented in \texttt{/llms.txt} and the booking portal.
\end{enumerate}

\textbf{Steps to Reproduce}
\begin{enumerate}[leftmargin=1.5em]
  \item Query: \textit{``Kho 3m\textasciicircum 3 dùng gói Basic được bồi thường tối đa bao nhiêu ?''}
  \item Follow-up Query: \textit{``MyStorage có gói bảo hiểm Bạc, Vàng, Bạch kim không''} (or Silver, Gold, Platinum).
\end{enumerate}

\textbf{Why it Matters}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Lost Upsell Revenue:} Prospective customers are never introduced to high-margin paid protection tiers (50k--200k VND/month), leading to immediate pipeline leakage.
  \item \textbf{Legal Liability \& Trust Collapse:} Customers are led to believe their 3 m\textsuperscript{3} unit is insured up to 10M VND. If items are damaged, MyStorage contractually pays only 1.5M VND $\rightarrow$ triggering severe customer disputes, negative reviews, and legal exposure.
\end{itemize}

\textbf{Severity:} \severitycritical

\textbf{Proposed Fix:} Implement a deterministic Python tool \texttt{calculate\_insurance(cbm, plan)} to calculate exact mathematical payouts rather than relying on probabilistic LLM arithmetic, enforced by strict system prompt guardrails.
\end{criticalbox}

\subsection*{Finding 2: Hallucination of Language-Specific Branch Hotlines \& Mobile Numbers}

\begin{highbox}
\textbf{What Happened:} When urgently requesting contact channels, STOW extrapolated numeric patterns from the single official landline (\texttt{028 7770 0117}) and invented fictional branch lines and an unauthorized mobile number:
\begin{itemize}[leftmargin=1.5em]
  \item Vietnamese Support: \texttt{028 7771 0118} \textit{(Hallucinated)}
  \item Korean Support: \texttt{028 7771 0119} \textit{(Hallucinated)}
  \item Japanese Support: \texttt{028 7771 0120} \textit{(Hallucinated)}
  \item Emergency Warehouse Access: \texttt{0868 208 079} \textit{(Hallucinated mobile number)}
\end{itemize}

\textbf{Steps to Reproduce:} Query: \textit{``tui muốn liên hệ gấp với bên stow thì nên dùng đường dây nào vậy hãy liệt kê các đường dây nóng mà cậu có đi''}

\textbf{Why it Matters:} During critical operations (e.g., customers locked out of 24/7 self-service facilities at night), calling disconnected or unmonitored numbers leads to acute frustration, operational failure, and severe brand damage.

\textbf{Severity:} \severityhigh

\textbf{Proposed Fix:} Integrate a dedicated \texttt{get\_contact\_info()} tool returning strictly the centralized hotline \texttt{028 7770 0117} and email \texttt{hello@mystorage.vn}, coupled with negative prompt constraints preventing fictional extensions.
\end{highbox}

\subsection*{Finding 3: Missing Direct Booking Call-To-Action (CTA) Leading to Funnel Drop-off}

\begin{mediumbox}
\textbf{What Happened:} After successfully assisting with unit sizing or pricing inquiries, STOW concludes conversations passively (\textit{``Do you have any further questions?''}) without presenting an actionable booking link or CTA button directing users to the official booking flow (\url{https://booking.mystorage.vn/en/book?step=service}).

\textbf{Steps to Reproduce:} Ask STOW to estimate space for 2 motorbikes and 10 storage boxes, then ask how to proceed with rental.

\textbf{Why it Matters:} Introduces unnecessary friction into the sales pipeline. High-intent customers must navigate back to the main website to book, resulting in substantial conversion drop-off.

\textbf{Severity:} \severitymedium

\textbf{Proposed Fix:} Introduce a dynamic booking CTA trigger into the agent's workflow, automatically generating parameterized booking links upon resolving sizing intent.
\end{mediumbox}

\section{What Claude Code Produced That I Rejected or Rewrote, and Why}

\begin{quote}
\itshape
``What 'AI-native' means here: Claude Code is our default way of building. You read every line the model produces and you can defend it in review. If you can't explain it, it doesn't ship.''
\end{quote}

\begin{itemize}[leftmargin=1.5em]
  \item \textbf{What Was Rejected:} When prompted to address the insurance calculation discrepancy, the AI assistant initially generated an extended \textbf{System Prompt Engineering} solution---attempting to instruct the LLM to perform inline arithmetic within its generation chain.

  \item \textbf{Why It Was Rejected:} Large Language Models are fundamentally probabilistic token predictors, not arithmetic engines. Relying strictly on prompt instructions for financial payouts and policy calculations is fragile and prone to failure under complex customer phrasing or multi-turn dialogues. In a live commercial pipeline, mathematical inaccuracies create unacceptable operational and legal risks.

  \item \textbf{What Was Rewritten:} I rejected prompt-based arithmetic and engineered a \textbf{Deterministic Python Tool} (\texttt{calculate\_insurance}) hooked into a LangGraph ReAct agent. The LLM handles natural language understanding and parameter extraction, while Python code guarantees 100\% arithmetic accuracy.
\end{itemize}

\section{Short Note for Application Endpoint (\textless{} 300 words)}

\begin{quote}
\itshape
``What's the last thing you built with an AI coding tool, and what did you have to fix yourself?''
\end{quote}

\begin{tcolorbox}[
  colback=MyLight,
  colframe=MyBorder,
  boxrule=0.6pt,
  arc=2mm,
  left=4mm,right=4mm,top=3mm,bottom=3mm
]
The last system I built with an AI coding tool is \textbf{STOW 2.0}, an AI-native customer assistant prototype designed to eliminate hallucinations in MyStorage's sales conversations.

While using AI coding assistants to scaffold the architecture, the model initially attempted to resolve calculation errors and contact hallucinations purely through \textbf{extended system prompt engineering} (relying on the LLM's internal reasoning to do arithmetic in-flight).

I rejected this approach because language models are inherently probabilistic; relying on prompt instructions for dynamic pricing, volume-based insurance math, and contact invariants inevitably fails under conversational pressure or complex customer prompts.

I intervened and rewrote the solution into a \textbf{hybrid Agentic Tool-Calling architecture} using Python and LangGraph. I built deterministic tools (\texttt{calculate\_insurance} and \texttt{get\_contact\_info}) so that math computations ($\min(V \times 500{,}000,\ 10{,}000{,}000)$) are strictly executed by deterministic Python code rather than token prediction. Additionally, when setting up the model connection, I diagnosed and resolved transport timeout issues on Windows by explicitly configuring REST transport over default gRPC framing.

The result is a robust, production-ready agent that achieved a \textbf{100\% pass rate} across our automated evaluation benchmark suite, ensuring zero hallucinations on emergency contact numbers and absolute mathematical precision in insurance calculations.
\end{tcolorbox}
